# Clarify Before Act

在错误猜测会造成明显返工时，先用一次简短确认让用户决定关键路径；简单且可低成本试错的任务直接执行。

## 适用范围
- 多种架构方案之间存在难以逆转的取舍。
- 目标含糊、文件位置选错会影响多个调用点、操作有破坏性，或成本/限流影响需要用户权衡。
- 跳过条件：只有一种明显路径、可便宜试错，或用户已经回答过。

## 内容结构
1. **触发清单**：判断何时询问、何时跳过。
2. **单消息确认模板**：一句话概述任务、推荐路径及理由，最多提出 3 个真正影响方案的问题。
3. **执行门槛**：发出确认后停止工具操作，等用户明确回复。
4. **反模式与范例**：避免把所有选项丢给用户或询问无关细节。

## 边界
不把日常可逆操作升级成审批；推荐一个方案，而不是罗列菜单。
