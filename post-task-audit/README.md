# Post-Task Audit

使用全新上下文的只读审查者，从独立视角检查已完成的重要任务。

## 内容结构
1. **启动条件**：用户要求、发布物、安全/破坏性操作、多文件或 ≥30 行改动、含糊验收。
2. **审查模式**：默认一个 `goal-verify`；确有不同专业维度时才并行多审查者。
3. **审计维度**：正确性、规范、安全、性能、文档一致性、用户意图。
4. **Prompt 规范**：原始请求、交付声明、限定维度与范围、只读边界、固定返回格式。
5. **处理发现**：先修 BLOCKER，便宜的 MAJOR 尽量修；修复后由新上下文复审。
6. **用户交付格式**：报告审计员、结论、各严重级别数量及未覆盖范围。

## 独立性
执行者不得自审；审计不能替代破坏性操作所需的用户确认。
